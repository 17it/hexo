## 二、项目结构

```
hexo/
├── _config.yml            # 站点主配置（站点信息、URL、目录、写作、部署等）
├── build.sh               # 一键构建部署脚本（clean → generate → deploy）
├── package.json           # 依赖与脚本（npm run h 触发 build.sh）
├── package-lock.json
├── db.json                # Hexo 运行时缓存（已生成的站点数据，可删）
├── debug.log              # 调试日志
├── scaffolds/             # 新建文章/页面模板（front-matter 骨架）
│   ├── post.md            # 文章模板
│   ├── page.md            # 页面模板
│   └── draft.md           # 草稿模板
├── source/                # 原始内容目录（仅此目录会被渲染处理）
│   ├── _posts/            # 文章（支持文章同名资源文件夹，见编码规范）
│   │   ├── *.md
│   │   ├── <文章名>/      # 与文章同名的资源目录（post_asset_folder）
│   │   └── img/...        # 文章内嵌图片
│   ├── about/             # 关于页（index.md）
│   ├── categories/        # 分类页占位（index.md）
│   ├── tags/              # 标签页占位（index.md）
│   └── img/               # 站点级图片资源（当前为空）
├── themes/                # 主题目录
│   ├── next/              # NexT 主题（当前使用，268 文件）
│   │   ├── _config.yml    # 主题配置（菜单、样式、插件、SEO 等）
│   │   ├── layout/        # 页面模板（swig）
│   │   │   ├── _layout.swig     # 基础布局
│   │   │   ├── index.swig       # 首页
│   │   │   ├── post.swig        # 文章页
│   │   │   ├── page.swig        # 单页
│   │   │   ├── archive.swig     # 归档
│   │   │   ├── category.swig    # 分类
│   │   │   ├── tag.swig         # 标签
│   │   │   ├── _partials/       # 局部组件（头部/侧栏/评论等）
│   │   │   ├── _macro/          # 复用宏
│   │   │   ├── _third-party/    # 第三方集成（统计、分享等）
│   │   │   └── _custom/         # 自定义注入
│   │   ├── source/        # 主题的 CSS/JS/图片资源（styl/js/svg/gif）
│   │   ├── languages/     # 多语言文案（13 种 yml）
│   │   └── scripts/       # 主题扩展脚本
│   └── landscape/         # 备用主题（默认主题，未启用）
└── public/                # 构建产物（由 source 生成，勿手动修改）
```

> **约定**：`source/` 是内容源，`public/` 是生成结果，二者不重叠；提交仓库时 `public/`、`db.json`、`debug.log` 通常应纳入 `.gitignore`。

## 三、技术栈与依赖

来自 `package.json`（Hexo 6.2.0）：

| 依赖 | 作用 |
| --- | --- |
| `hexo` | 核心框架 |
| `hexo-server` | 本地预览服务器（`hexo s`） |
| `hexo-generator-index` | 首页生成 |
| `hexo-generator-archive` | 归档页生成 |
| `hexo-generator-category` | 分类页生成 |
| `hexo-generator-tag` | 标签页生成 |
| `hexo-renderer-ejs` | EJS 模板渲染 |
| `hexo-renderer-marked` | Markdown 渲染 |
| `hexo-renderer-stylus` | Stylus 样式渲染 |
| `hexo-renderer-swig` | Swig 模板渲染（NexT 主题依赖） |

渲染器链：`.md` → `marked` 渲染正文，`swig`/`ejs` 渲染布局，`stylus` 处理样式。

## 四、编码规范

### 4.1 文章 Front-Matter 规范

每篇文章顶部需包含 YAML 头信息（与 `scaffolds/post.md` 一致）：

```yaml
---
title: 文章标题
date: 2021-03-16          # 发布日期（也可含时间 2021-03-16 14:22:48）
categories: web           # 分类（单值或多值）
tags:                     # 标签（列表形式，缩进 4 空格）
    - web
    - proxy
#description:             # 可选摘要，默认取正文前段
---
```

- **缩进**：`categories`/`tags` 下一级使用 **4 个空格**缩进（与模板保持一致）。
- **`<!-- more -->`**：在正文合适位置插入，用于首页摘要截断（以上为摘要，点击展开全文）。

### 4.2 文章资源（post_asset_folder）

`_config.yml` 已开启 `post_asset_folder: true`，因此：

- 每新建/存放文章时，可在 `source/_posts/` 下建立与文章**同名目录**存放配套图片。
- 配合 `hexo-asset-image`，正文中引用图片可使用相对路径（如 `![图](proxy代理/xxx.png)`），部署到 GitHub Pages 子路径时路径仍能正确解析。

### 4.3 写作与命名约定（来自现有文章）

- 文章文件名以中文标题命名（如 `proxy代理.md`、`正则.md`），少量英文/连字符命名（如 `Hello-world.md`、`Vue-cli快速搭建Vue.md`）。
- 系列文章使用「（一）（二）（三）」编号（如 `centos搭建rabbitmq（一）.md`）。
- 内容主题集中于：前端工程化（eslint / stylelint / husky / lint-staged）、框架实践（Vue / uni-app / Flutter / Micro-App）、运维部署（Linux / Nginx / 阿里云 / RabbitMQ / 日志系统）、算法与 JS 技巧、面试题等。

### 4.4 代码块规范

- 使用 Markdown 围栏代码块并标注语言（如 ` ```bash `、` ```js `），便于 `highlight` 高亮（已开启行号 `line_number: true`）。

## 五、功能构成

### 5.1 内容形态

| 类型 | 路径 | 说明 |
| --- | --- | --- |
| 文章（Post） | `source/_posts/*.md` | 博客正文，支持分类/标签/分页 |
| 单页（Page） | `source/about|tags|categories/index.md` | 关于、标签、分类独立页 |
| 草稿（Draft） | （草稿目录） | 未发布内容 |

### 5.2 站点功能（由生成器 + NexT 主题提供）

- **首页列表**：`per_page: 10` 分页展示文章摘要。
- **归档 / 分类 / 标签**：由对应 generator 自动生成，菜单可直达。
- **永久链接**：`permalink: :year/:month/:day/:title/`（按日期+标题）。
- **代码高亮**：内置 highlight（行号开启）。
- **RSS / SEO**：NexT 主题已开启 `canonical`、`seo` 配置，支持 RSS。
- **菜单**：首页 / 分类 / 标签 / 归档 / 关于 / 404，配 FontAwesome 图标。
- **多语言**：NexT 内置 13 种语言文案，站点使用 `zh-Hans`。

### 5.3 主题能力（NexT）

布局基于 `swig` 模板，组件化于 `_partials`/`_macro`，并通过 `_third-party` 集成统计、分享等；样式由 `stylus`（`source/*.styl`）构建。

## 六、构建与部署

### 6.1 本地预览

```bash
hexo s          # 启动本地服务器（默认 http://localhost:4000）
```

### 6.2 一键构建部署（build.sh）

`package.json` 中脚本 `h` 即执行 `build.sh`，流程：

```bash
rm -f db.json          # 清除旧缓存
hexo clean             # 清空 public 与缓存
hexo g                 # 生成静态文件到 public
hexo d                 # 部署到 GitHub Pages
```

运行方式：

```bash
npm run h
```

### 6.3 部署目标

- 类型：`git`
- 仓库：`https://github.com/17it/17it.github.io.git`（配置中已写入带 token 的地址，**注意脱敏**，建议改用环境变量或 SSH）
- 分支：`master`

> ⚠️ 当前 `_config.yml` 的 `deploy.repo` 含明文 token，存在安全风险，建议改为 SSH（`git@github.com:17it/17it.github.io.git`）或 CI 注入。

## 八、维护建议

1. **敏感信息**：移除 `_config.yml` 中部署 token，改用 SSH 或 CI 变量。
2. **忽略产物**：将 `public/`、`db.json`、`debug.log`、`.idea/` 加入 `.gitignore`，仅提交 `source/`、`scaffolds/`、`themes/`（或主题子模块）、配置文件。
3. **主题升级**：NexT 通过 `themes/next` 内嵌管理，升级时优先备份其 `_config.yml` 自定义项。
4. **图片管理**：统一使用文章同名资源目录 + 相对路径，避免仓库路径错乱。
